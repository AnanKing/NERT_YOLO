# NERT-YOLO

PyTorch implementation for forest fire and smoke detection, including DMO reparameterized bottlenecks, the C2LS feature aggregation module, and the NFEH NMS-free detection head. Supports training, validation, image and video inference, structural fusion, model export, and performance benchmarking.

## Installation

Use Python 3.10–3.12 and run the following commands from the project root:

```bash
python -m venv .venv
```

Activate the environment in Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Activate the environment in Linux or macOS:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

For GPU environments, first install PyTorch 2.5.1 and torchvision 0.20.1 versions compatible with the installed driver, then install the remaining dependencies. Ultralytics is pinned to 8.3.0.

## Dataset

Modify `configs/data.example.yaml` and set `path` to the absolute path of the dataset root directory. Class IDs must match the annotations; examples are `0: fire` and `1: smoke`.

```text
fire_smoke/
  images/train/
  images/val/
  images/test/
  labels/train/
  labels/val/
  labels/test/
```

Each image corresponds to a `.txt` annotation file with the same name. Each line has the following format:

```text
class_id center_x center_y width height
```

Coordinates are normalized by image width and height to the range 0–1. Negative samples use empty annotation files.

## Training

```bash
python run.py train --data configs/data.example.yaml --device 0
```

Run on CPU:

```bash
python run.py train --data configs/data.example.yaml --device cpu --batch 2
```

Resume training from a checkpoint:

```bash
python run.py train --model runs/train/nert/weights/last.pt --data configs/data.example.yaml --device 0 --resume
```

`configs/train.yaml` defines the optimizer, learning rate, input size, batch size, and augmentation settings. Training defaults to 200 epochs with an SGD optimizer and a 640×640 input. Training outputs include checkpoints, configuration, and metric logs.

## Validation and Inference

```bash
python run.py val --weights runs/train/nert/weights/best.pt --data configs/data.example.yaml --split test --device 0
python run.py predict --weights runs/train/nert/weights/best.pt --source images/ --device 0 --conf 0.25 --max-det 300
python run.py predict --weights runs/train/nert/weights/best.pt --source video.mp4 --device 0
```

The default validation confidence threshold is 0.001, while the default prediction threshold is 0.25. The `max-det` inference option controls the number of outputs. Training label assignment uses Top-K values of 10 and 1, respectively.

## Structural Fusion and Export

```bash
python run.py deploy --weights runs/train/nert/weights/best.pt --output nert-deploy.pt
python run.py predict --weights nert-deploy.pt --source images/ --device 0
python run.py export --weights nert-deploy.pt --format torchscript --device cpu
python run.py export --weights nert-deploy.pt --format onnx --device cpu
```

DMO fusion uses BatchNorm running statistics and preserves the ReLU between spatial and pointwise convolutions. The fused checkpoint is used for inference, while resumed training uses the unfused `last.pt`. NFEH inference calculates only the one-to-one branch.

TorchScript uses a fixed input size. ONNX export additionally requires `onnx`, `onnxslim`, and `onnxruntime`. The deployment backend must support the operators involved in dynamic local aggregation.

## Benchmarking

```bash
python run.py benchmark --weights nert-deploy.pt --device cuda:0 --batch 1 --warmup 20 --iterations 100
```

The tool first fuses DMO and standard Conv-BN modules, then reports the device, precision, input shape, warmup iterations, latency, and throughput. Timing includes model forward propagation, decoding, and Top-K, but excludes image reading, resizing, data transfer, and final threshold filtering.

The reported operation count covers convolutions and locally weighted summation. Each multiply-add counts as two operations. BN, activations, softmax, decoding, and Top-K are excluded from the operation count.

## Model Configuration

`configs/nert.yaml` defines the network connections, channels, and repetition counts. The default backbone and neck dilation rates are 1, 1, 2, and 3, and DMO uses 3 branches. C2LS uses G=4, Ks=3, one LSBlock, and an FFN expansion ratio of 2. Local aggregation uses native PyTorch unfold operations and softmax-normalized weights.

Channel scaling in this repository follows the YOLO11n baseline. The configuration above defines the specific settings for this implementation. Training weights and datasets must be prepared separately, and detection metrics are generated by actual training and evaluation.

The component ablation uses fixed channel widths and repetition counts:

```bash
python tools/make_variants.py
python run.py train --model configs/baseline.yaml --data configs/data.example.yaml --name baseline --device 0
python run.py train --model configs/dmo.yaml --data configs/data.example.yaml --name dmo --device 0
python run.py train --model configs/c2ls_only.yaml --data configs/data.example.yaml --name c2ls_only --device 0
python run.py train --model configs/dmo_c2ls.yaml --data configs/data.example.yaml --name dmo_c2ls --device 0
```
